# 脚本管理：Excel → JSON 导入导出改造

## 背景与根因

- 现状：`scriptExcelComponents.js`（784 行）的 Excel 导入/导出不导出 `category_id` 与目录树、不注册自定义标签值到 `tag_values` 表，导致目录结构与自定义标签无法还原。
- 决策：删除 Excel 链路，改用 JSON 无损格式；用户确认无历史 Excel 数据需回导；同名脚本冲突采用**覆盖更新**；「单独导入 .sh」升级为**多选批量导入**。
- 主机管理（`hostService.importFromExcel`、`components.js`）、执行结果导出（`commandExecution.js` / `taskExecution.js`）的 Excel 功能**保持不变**，`xlsx` 依赖保留。

## JSON 备份格式（version 1）

```json
{
  "format": "wanxiang-scripts-backup",
  "version": 1,
  "exportedAt": "ISO-8601",
  "categories": [ { "id": 12, "name": "运维工具", "parent_id": null, "sort_order": 0 } ],
  "tagValues": [ { "typeId": 4, "value": "巡检" } ],
  "scripts": [ { "name", "description", "content", "category", "category_id", "language", "tags": [{"typeId","typeName","value"}], "author", "usage_notes" } ]
}
```

- `categories`：`script_categories` 全表（含 parent_id 层级），导入时按「同父目录下同名」匹配，缺失则 `category:create` 重建，并建立 `旧id → 新id` 映射。
- `tagValues`：全量导出；导入时对本地不存在的值调 `tag:createValue(typeId, value)` 补建（系统类型 1-3 的值也补，幂等）。
- `scripts`：`tags` 用 `formatScript` 输出的 `{typeId, typeName, value}` 结构，无损往返。

## 改动清单

### 1. 删除 Excel 链路

- `src/renderer/js/scriptExcelComponents.js`：删除 `ScriptExcelImportDialog`（L1-312）、`ScriptExcelExportDialog`（L314-624）两个类及底部两个 window 导出；保留 `ScriptShImportDialog`、`escapeShHtml`。文件只剩 .sh 导入对话框，重命名为 `src/renderer/js/scriptImportComponents.js`，并新增下述 JSON 对话框类。
- `src/renderer/index.html` L1081：`script src` 改为 `js/scriptImportComponents.js`。
- `src/renderer/js/services/scriptService.js`：删除死代码 `exportScript()`（L370-391）、`importScript()`（L393-408）、`importFromExcel()`（L410-453）——全项目无其他引用，已 grep 确认。

### 2. 新增 JSON 导入导出（`scriptImportComponents.js` 内）

**`ScriptJsonExportDialog`（轻量，或直接函数）**
- 收集数据：`scriptService.loadScripts()`（全量，不限当前筛选）、`categoryService.getAll()`、`tagService.getAllWithValues()`（导出为 `{typeId, value}`）。
- 按 version 1 格式组装，`JSON.stringify(data, null, 2)`。
- Electron：`ipcRenderer.invoke('save-data-file', buffer, '脚本备份_时间戳.json', 'json')`；非 Electron 走浏览器 Blob 下载（沿用原 Excel 导出的降级写法）。

**`ScriptJsonImportDialog`**
- 文件选择器（`accept=".json"`）→ FileReader 解析 → 校验 `format`/`version`/`scripts` 数组。
- **预览阶段**（本地只读计算，不写库）：
  - 加载本地 `categoryService.getAll()`、`tagService.getAllValues()`、`scriptService.getAllScripts()`；
  - 计算待新建目录数（含路径如 `运维工具/日志清理`）、待补建标签值数、新脚本数、同名冲突数（按 name 匹配）；
  - 弹窗展示汇总 + 冲突明细（前 N 条），确认按钮文案「开始导入」。
- **执行阶段**（事务顺序）：
  1. 按父→子顺序创建缺失目录，建立 `旧id → 新id` 映射；
  2. 逐个补建缺失标签值（先 `getAllValues` 刷新缓存再 createValue，避免重复）；
  3. 逐脚本导入：`category_id` 经映射转换；`tags` 传 `[{typeId, value}]`（`ScriptModel.create` 原生支持）；同名冲突调 `scriptService.updateScript(本地id, data)` 覆盖更新，否则 `addScript`；
  4. 每脚本 try/catch 收集错误行，最终汇总 `imported / updated / errors` 通知。
- 导入完成回调 `loadCategories() + loadScripts()` 刷新页面。

### 3. `save-data-file` IPC（`src/main/main.js`）

- 参照现有 `save-excel-file`（L1008-1035）新增通用处理器：参数 `(buffer, defaultFileName, ext)`，filters 按 ext 分派（json → `[{name:'JSON文件', extensions:['json']}]`），`fs.writeFileSync` + `shell.showItemInFolder`，返回 `{success, filePath, fileName}` / `{success:false, canceled:true}`。
- 不改动 `save-excel-file`（主机/结果导出仍在用）。

### 4. 按钮与入口（`src/renderer/index.html` + `scriptManagement.js`）

- index.html L213-215 三个按钮改为：
  - `importSingleScriptBtn`「导入 .sh」（文案微调，id 不变）
  - `importScriptJsonBtn`「导入备份」（新 id，替换 `importScriptExcelBtn`）
  - `exportScriptJsonBtn`「导出备份」（新 id，替换 `exportScriptExcelBtn`）
- `scriptManagement.js`：
  - 事件绑定（L48-61）改为绑 `importScriptJsonBtn` → 打开 `ScriptJsonImportDialog`；`exportScriptJsonBtn` → 执行 JSON 导出；`importSingleScriptBtn` 保留。
  - 删除 `importScripts()`（Excel 版，L1249-1261）、`exportScripts()`（L1264-1280），替换为 JSON 版函数。
- `importSingleScript`（L1207-1246）：`fileInput` 加 `multiple`；读取所有选中文件后弹**一个**确认对话框：脚本归属目录统一选一次 + 文件列表（默认名=去后缀文件名）；确认后循环 `addScript`，汇总成功/失败通知。`.sh` 多文件仍复用现有 FileReader 读取逻辑（`Promise.all` 包裹）。

## 验证计划

1. `npm start` 启动应用，脚本管理页：
   - 构造含两级目录（父/子）、自定义标签值、多脚本的库 → 「导出备份」→ 检查 JSON 结构完整（categories 含 parent_id、tagValues、scripts 含 category_id 与结构化 tags）。
   - 清空库（或换测试库）→ 「导入备份」→ 验证：目录树原样重建（层级/顺序）、自定义标签出现在标签筛选面板、脚本落在正确目录下、tags 无损。
   - 同名覆盖：导入含同名脚本的备份 → 确认本地脚本被更新而非重复。
   - 「导入 .sh」多选 3 个文件 → 一次选目录 → 3 条全部入库。
2. 主机管理 Excel 导入导出、执行结果导出回归不受影响（未触碰）。
3. `GetProblems` 检查改动文件无语法/引用错误。

## 假设

- 非浏览器环境（demo/website）脚本页本身依赖 Electron IPC，JSON 导出降级路径只为保底，不重点测试。
- 不做增量/合并选项（如只导出筛选结果），本次全量导出；后续有需要再加。
