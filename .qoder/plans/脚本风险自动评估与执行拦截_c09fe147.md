# 脚本风险自动评估与执行拦截

## 核心设计

- **判定标准 = 可逆性**：高危=不可逆损失（全盘删除、块设备覆写），中危=可恢复但影响大（服务中断、权限失控），普通=其余
- **打标全收口在 scriptService**：所有写入口（编辑/复制/JSON 导入/.sh 导入/Excel 导入）统一自动重算 typeId=3 标签，禁止人工写入
- **拦截只做 renderer 侧**：三个执行入口在创建任务前弹窗；定时任务创建时已拦截、到点运行不弹（避免无人值守卡死）；主进程 taskExecutor 不做二次拦截
- **v1 不做评分公式**：直接取命中规则的最高等级；findings 结构化输出供展示与后续 AI 使用

## 1. 规则引擎（新文件 `src/renderer/js/services/riskAnalyzer.js`）

纯函数，零依赖，暴露 `window.RiskAnalyzer = { analyzeRisk, LEVELS, LEVEL_NAMES }`。

```
analyzeRisk(content) → {
  level: 'high' | 'medium' | 'normal',
  findings: [{ level, ruleId, message, line, snippet }]   // 供 UI 展示 & AI 后续复用
}
```

流程：剥离注释（保留 shebang）→ 逐条规则匹配（多行正则容忍折行 `\s*\|\s*`）→ 取最高命中等级。

规则库（取自 docs/features/shell.md 并按可逆性归档）：

| 档位 | ID | 规则 |
|---|---|---|
| 高危 | H1 | `rm -rf/fr` 目标为 `/`、`/*` 或系统目录（bin/boot/dev/etc/lib/lib64/proc/root/sbin/sys/usr/var/home） |
| 高危 | H2 | `rm -rf $VAR/*` 且同行无 `${VAR:?...}` 空值防护 |
| 高危 | H3 | `mkfs` / `fdisk` / `parted` / `wipefs` / `shred` |
| 高危 | H4 | `dd of=/dev/sd*|nvme*|vd*|mmcblk*` |
| 高危 | H5 | `curl/wget ... \| bash/sh`（跨行容忍） |
| 高危 | H6 | `eval $1/$@/$*` 等不可信输入直执、`sh -c "$var"` |
| 中危 | M1 | `chmod 777` / `chmod -R 777` |
| 中危 | M2 | `kill -9 1` / `killall` / `pkill -9` |
| 中危 | M3 | 防火墙关闭：`iptables -F`、`systemctl stop firewalld`、`ufw disable` |
| 中危 | M4 | 重启关机：`shutdown`/`reboot`/`halt`/`poweroff`/`init 0`/`init 6` |
| 中危 | M5 | sudoers 修改 / `NOPASSWD` |
| 中危 | M6 | 明文凭据赋值 `(password|passwd|secret|token|api_key|private_key)\s*=\s*['"][^'"]+['"]` |
| 中危 | M7 | 通用 `eval` 使用（非 H6 场景） |
| 中危 | M8 | `systemctl stop/restart sshd`（断自身连接） |

说明：shell.md 原四档（L1~L4）按本目标归拢——L3/L4 规范性问题（缺 `set -euo pipefail`、反引号等）v1 不实现；明文凭据从 L1 降为中危（属泄漏风险而非不可逆操作）。

## 2. 自动打标收口（`src/renderer/js/services/scriptService.js`）

- 新增私有方法 `applyAutoRiskTag(scriptData)`：删除入参 tags 中 typeId===3 的项 → `analyzeRisk(content)` → level≠normal 时注入 `{ typeId:3, typeName:'风险等级', value:'高危'|'中危' }`
- `addScript`、`updateScript`（Electron 分支传 IPC 前、非 Electron 分支入库前）统一调用
- 数据库结构不动（typeId=3 复用），仅值域增加「中危」
- 注意：JSON 备份导入的旧标签会被自动重算覆盖（预期行为，保证一致性）

## 3. 编辑弹窗改造（`src/renderer/js/scriptManagement.js`）

- 删除标签区第 4 列「风险」下拉 + 「加」按钮，替换为只读评估徽标：`自动评估：高危/中危/普通`（高危红/中危黄/普通绿）+ 命中明细（规则说明 + 行号，hover 或内联展示）
- 复用 `#scriptContent` 已有 300ms input debounce，同一监听里调 `analyzeRisk` 更新徽标
- 编辑已有脚本打开弹窗时立即分析一次（不信任存量标签）
- 标签过滤下拉 `updateTagValueFilter`：typeId===3 固定值 `['普通','高危']` → `['中危','高危']`
- 工具栏加「重新评估风险」按钮：遍历所有脚本 updateScript 重算（处理存量人工标签，不做启动时自动迁移）

## 4. 执行链路拦截（三个入口 + 强确认弹窗）

**弹窗逻辑**（`riskAnalyzer.js` 内实现 `RiskGate.confirm({ name, content })` → `Promise<boolean>`）：
- 现场调用 `analyzeRisk(content)`（不信任存量标签）
- **高危**：强确认弹窗——展示命中规则、行号、代码片段；勾选「我已知晓此操作可能造成不可逆损失」且手动输入脚本名/命令名，两个条件都满足才亮起确认按钮
- **中危**：复用 `Components.ConfirmDialog` 普通确认，提示命中要点
- **普通**：直接放行（不弹窗）

**接入点：**

| 文件 | 位置 | 说明 |
|---|---|---|
| `taskExecution.js` | `startExecution()`，`createTask` 之前 | 从 allScripts 取脚本对象，用其 content 走 RiskGate |
| `commandExecution.js` | `startExecution()`，`createTask` 之前 | 临时命令无标签，直接对 commandText 走 RiskGate |
| `projectTaskExecution.js` | `startExecution()`，`getSvc().execute` 之前 | 从任务定义收集所有 script/command 步骤内容合并分析，弹窗按步骤展示命中 |
| 定时任务 | — | 创建时经上述入口已拦截；taskScheduler 到点执行不弹窗 |

## 5. 选择器可视化（`taskExecution.js`）

- `renderScriptPicker` 列表项加风险徽标（高危红/中危黄），高危脚本默认可见警示
- 脚本管理列表复用现有 `.tag-chip.risk` / `.high` 样式，自动标签自然生效，无需改动

## 6. AI 预留

- `analyzeRisk` 输出结构化 findings（ruleId/level/message/line/snippet），后续 AI 模块可：拿脚本 + 规则命中结果做二次判定，覆盖 level——对上层调用方（service 打标、RiskGate）接口零变更

## 测试计划

- 规则引擎纯函数用 node 临时脚本验证：各档位命中样例、注释不误报（`# rm -rf /`）、`${VAR:?}` 防护豁免、跨行 `curl | bash`、空脚本/shebang-only 脚本返回 normal
- 手工验证：编辑弹窗实时徽标与明细、保存后列表标签正确、三处执行入口按档位弹窗（高危需输入名称才能确认）、批量重估按钮、JSON 导入后标签被重算
- 回归：编辑弹窗其余标签功能（环境/架构/自定义）不受影响

## 假设

- 「普通」= 无风险标签（不写 typeId=3），沿用现有「普通」语义
- 拦截策略可被用户明确取消后放行本次（不记住选择，每次执行重新确认）
- 不改主进程与数据库；index.html 需追加 riskAnalyzer.js 的 script 引用
