# AI 请求日志与审计功能

## 目标
- 每次 AI 请求（分析 / 生成 / 测试连接）都有持久化记录：时间、来源、模型、状态、HTTP 状态码、耗时、token、错误原文、响应预览
- 超时等失败可通过记录定位根因（超时 vs 网络错误 vs 网关 4xx/5xx）
- 提供「记录完整请求体」开关（默认关闭）满足强审计需求
- 新增「AI 请求记录」页面：列表 + 筛选 + 详情弹窗 + 清空

## 一、主进程 src/main/aiService.js（核心埋点）

1. 新增常量：`REQUEST_LOG_TABLE = 'ai_request_logs'`、`MAX_REQUEST_LOGS = 200`（滚动淘汰）
2. `chat()` 签名增加 `purpose`（analyze/generate/test）与 `scriptId/scriptName` 上下文，内部完整埋点：
   - 记录：endpoint host（不记完整 URL）、model、超时阈值、开始时间、耗时
   - 成功：http_status、usage、response_preview（前 500 字符）
   - 失败：错误类型区分（timeout / network / http_{status} / bad_response），error 原文
   - 返回值附带 `logId`，供 analyze 层回填 parse_error 状态
   - 失败时 `console.warn` 打一行摘要（purpose/host/duration/error）便于开发调试
3. 请求全文审计开关：
   - `getSettings()`/`saveSettings()` 增加 `logFullRequest`（默认 false）
   - 开启时记录 `request_body`（完整 messages JSON）；默认只记 `request_chars`
   - 写库失败 try/catch 包裹，不影响 AI 主流程
4. `analyze()`：调用 chat 传 purpose='analyze' + 脚本上下文；JSON 解析失败时回填日志状态为 `parse_error`
5. `generateScript()`：purpose='generate'；`testConnection()`：purpose='test'（默认开关下也记录，方便排查连接问题）
6. 新增 `getRequestLogs()`（倒序返回全部，≤200 条）与 `clearRequestLogs()`

## 二、数据库 src/database/simple-db.js

- `DEFAULT_DATA` 增加 `ai_request_logs: []`（旧库文件加载时自动补默认结构，无需迁移脚本）

## 三、主进程 IPC src/main/main.js

- `ai:getRequestLogs` → `{ success, data }`
- `ai:clearRequestLogs` → 清空
- `ai:saveSettings` 无需改动（透传 payload.logFullRequest）

## 四、渲染层服务 src/renderer/js/services/aiService.js

- 新增 `getRequestLogs()`、`clearRequestLogs()` IPC 封装

## 五、新页面「AI 请求记录」

1. **index.html**：
   - 侧边栏「任务记录」之后新增 nav-item `data-page="ai-logs"`（聊天图标）
   - 新增 `#page-ai-logs` 页面容器：表头（时间/来源/脚本/模型/状态/HTTP/耗时/Token/操作）+ 工具栏（刷新、状态筛选、来源筛选、清空按钮）
   - 引入 `js/aiRequestLogs.js`
2. **新文件 src/renderer/js/aiRequestLogs.js**（window.AiRequestLogs，参考 TaskHistory 模式）：
   - 列表渲染：状态徽章（成功/失败/超时/解析失败）、耗时人性化（>10s 橙色提示）、token 数
   - 筛选：状态、来源（分析/生成/测试连接）
   - 详情弹窗：元信息 + 错误原文 + 响应预览 + 请求全文（仅开关开启时有；含敏感信息提示）+ 复制按钮
   - 清空：ConfirmDialog 确认后调用 IPC
3. **navigation.js**：`pages.set('ai-logs', ...)` + `loadAiLogsPage()`

## 六、设置弹窗 app.js（大模型接入分组）

- 新增「记录完整请求体（审计）」checkbox，保存时随 `ai:saveSettings` 提交
- 开关旁提示：开启后每次请求的完整 Prompt（含脚本内容）将明文记录在本地数据库，注意数据安全
- 新增「查看请求记录」按钮跳转 ai-logs 页面

## 隐私与安全约束
- 永不记录 Authorization header / API Key
- 默认不落请求全文，仅字符数；endpoint 只记 host
- 响应预览截断 500 字符；请求全文开关默认关闭且有明确警告

## 测试计划
- 主进程语法检查 `node -c`
- 手动路径：测试连接（成功/失败各一条）→ 单脚本分析 → 请求记录页查看列表与详情 → 开启审计开关后重新分析验证全文落库 → 清空功能
- 验证滚动淘汰：逻辑审查（>200 条删最旧）
- 验证旧库兼容：无 ai_request_logs 键的 database.json 加载正常
