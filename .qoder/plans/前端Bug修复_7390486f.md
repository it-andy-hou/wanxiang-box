# 前端 Bug 修复计划

## Bug 1: 文件上传页事件重复绑定

**文件**: `src/renderer/js/fileUpload.js`

**根因**: 模块加载时自动执行 `init()`(第1165-1170行)未设置 `_initialized` 标志,首次导航到该页时 `FileUploadPage.init()` 再次执行 `init()` → `bindEvents()` 被调用两次,所有按钮监听器重复绑定。

**修复**: 在 `bindEvents` 函数内部加幂等守卫(模块级闭包变量 `eventsBound`),已绑定时直接返回。最小改动,不改变现有初始化流程。

```javascript
let eventsBound = false;
function bindEvents() {
    if (eventsBound) return;
    eventsBound = true;
    ...
}
```

## Bug 2: IPC 进度监听器异常路径泄漏(3处)

**根因**: `removeListener` 均位于 `ipcRenderer.invoke` 成功路径上;若 `invoke` 抛出异常(主进程错误),监听器永久残留,后续批量操作时进度回调被重复执行。

### 2.1 `src/renderer/js/services/hostService.js` (batchTestConnectionConcurrent, 约787-853行)
- 将 `ipcRenderer.on('batch-test-progress', ...)` 到 `removeListener` 之间的逻辑包入 `try/finally`
- `finally` 中统一执行 `removeListener`

### 2.2 `src/renderer/js/app.js` (pingAllHosts, 约815-912行)
- `ipcRenderer.on('batch-ping-progress', progressHandler)` 后,将 `invoke` 与结果处理包入 `try/finally`
- `finally` 中执行 `removeListener('batch-ping-progress', progressHandler)`
- 注意: 保留外层既有的 `try/catch/finally`(loading overlay 隐藏逻辑不变),仅在 Electron 分支内部新增一层 `try/finally` 保护监听器清理

### 2.3 `src/renderer/js/components.js` (startConcurrentPingTest, 约2703-2789行)
- 同 2.2: 在 `ipcRenderer.on` 之后用 `try/finally` 包裹 `invoke` 及结果处理,`finally` 中移除监听器
- 保留既有 catch 回退串行模式逻辑不变

## 验证

1. `GetProblems` 检查三个文件无语法/编译错误
2. 人工核对: 每个 `ipcRenderer.on` 均有对应且不可跳过的 `removeListener`;`bindEvents` 守卫生效
