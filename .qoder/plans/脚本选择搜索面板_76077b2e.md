# 脚本执行页 · 脚本选择搜索面板改造

## 背景与目标
现状问题：
1. 原生 `<select>` 每行拼接「名称 - 描述 [标签] (时间)」长文本，脚本多时视觉混乱；
2. 目录+标签两个下拉是「选择前的准备步骤」，操作路径长、认知成本高；
3. 无搜索、无分组、无最近使用，高频脚本也要翻找。

目标：筛选内联到选择过程——「输入2~3个字 → 点击」或高频脚本直接单击完成选择。

## 一、HTML 结构（src/renderer/index.html L300-315）
替换 `te-script-filters` 两个下拉 + `<select id="taskScriptSelect">` 为：

```
┌ te-script-search ────────────────────────────┐
│ 🔍 [搜索输入框]        共N·匹配M   [×]       │
├ te-script-selected（选中后显示）──────────────┤
│ ✓ 已选：restart-nginx · 运维 / nginx         │
├ te-script-list（max-height 240px 滚动）──────┤
│ ▸ ⏱ 最近使用（仅无搜索/无标签过滤时）        │
│ ▸ 📁 目录分组（sticky 表头，可折叠）          │
│ ▸ 📁 未分类（末尾）                          │
└──────────────────────────────────────────────┘
<input type="hidden" id="taskScriptSelect">   ← 保持 id 不变
[查看内容] 按钮保留不动
```

行内容：名称（省略号）+ 标签chip（可点击toggle过滤）+ 相对时间（mono、右对齐）+ 选中行打勾高亮。

## 二、JS 逻辑（src/renderer/js/taskExecution.js）
### 删除
- bindEvents 中两个 filter change 监听（L137-147）及 taskScriptSelect change 监听（L66-69）
- `loadScriptCategories` 填充下拉逻辑（改为构建 categoryMap）
- `populateTagValueSelect`、`applyScriptFilters`、`renderScriptOptions` 三函数
- `handleScriptChange`（改写为 `selectScript(script)`）

### 新增/改写
1. **模块变量**：`categoryMap`（目录id→名称）、`recentScriptIds`、`activeTagFilter`、`pickerHighlightIndex`
2. **selectScript(script)**：写隐藏字段值 → 生成任务名（脚本名_YYYYMMDD_HHmmss，逻辑同原 handleScriptChange）→ 启用查看按钮 → 重渲染选中态
3. **renderScriptPicker()**：搜索词 + activeTagFilter 过滤 → 最近使用组（无搜索时）→ 目录分组 → 未分类；行渲染 + 选中高亮 + 计数提示
4. **handleScriptListClick**（事件委托）：tag chip 点击 → toggle 标签过滤；行点击 → selectScript
5. **handleSearchKeydown**：↑↓ 移动高亮、Enter 选中、Esc 清空
6. **getRecentScriptIds**：loadTaskHistory 内从 scriptTasks 按 created_at 倒序去重取前5
7. **formatRelativeTime**：刚刚/x分钟前/x小时前/x天前/日期
8. **reExecuteTask L1932**：`scriptSelect.value=...; dispatchEvent(change)` → `selectScriptById(task.script_id)`
9. showTaskConfig / resetTaskForm / loadScripts 同步改用新渲染函数并重置搜索状态
10. startExecution、handleViewScript 读隐藏字段 `.value`，**无需改动**

## 三、CSS（src/renderer/css/components.css）

- 新增 `.te-script-selected`（选中摘要条：primary-glow 底、check 图标）

## 假设
- 标签结构沿用现状兼容逻辑（`{value}` 对象数组或字符串数组）
- 不做拼音匹配（无拼音数据源），搜索为大小写不敏感的包含匹配
