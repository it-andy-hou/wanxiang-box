# Shell 脚本多层风险评估系统（Rule-AST + LLM 混合引擎）需求规格说明书

---

## 1. 项目背景与设计目标

为防止在运维自动化、批量作业分发及 CI/CD 流水线中发生误操作（如高危删除、误格式化）或恶意代码注入（如反弹 Shell、混淆执行），需构建一套针对 Shell 脚本的静态安全评估系统。

系统采用 **“确定性规则/AST 静态初筛 + LLM 语义与混淆深度仲裁”** 的双层混合架构：

* **确定性与实时性：** 毫秒级阻断确定性高危指令，支持完全离线及内网环境运行。
* **语义泛化与上下文理解：** 借助 AI Token 突破传统静态分析对动态拼接、变量扩展及意图识别的局限，输出可解释性风险评估与修复建议。

```

       ▼

│ - 真实调用提取 (CallExpr) 与高危命令/参数矩阵匹配       │
│ - 危险路径（根目录、空变量拼接）硬拦截                 │

└────────────────────────────────────────────────────────┘
       │

       │
       ▼

       │
       ▼
[综合审计报告 JSON / 拦截决策]

```

## 3. 功能模块详细需求

### 模块一：AST 语法树解析与结构化提取（确定性代码层）

* **AST 构建能力：**
* 使用标准的 POSIX/Bash 语法解析器（如 Go `mvdan.cc/sh/v3` 或 Python `bashlex`），将输入文本转化为抽象语法树。
* **必须排除非执行节点：** 明确剥离行内注释、Block 注释、HereDoc 文档及 `echo`/`printf` 内部的纯字面量字符串，避免模式匹配造成的误报。


* **调用节点提取（CallExpr Extraction）：**
* 提取所有真实命令调用节点，拆解为：`Command`（命令名）、`Flags`（选项参数）、`Args`（操作目标路径或参数）。
* 识别控制流结构（`if` 条件分支、`for/while` 循环、函数定义域）。



### 模块二：静态规则风险矩阵与模式库

系统需预置基于 AST 节点的分类检测规则，输出标准化风险项：

* **R1 - 破坏性系统变更（Block 级）：**
* 存储与文件系统操作：`mkfs`, `fdisk`, `parted`, `dd`（写入原始设备）。
* 关键系统状态控制：`reboot`, `shutdown`, `poweroff`, `init 0`。
* 极危删除组合：`rm` 携带 `-r`/`-f` 参数，且目标路径满足以下任一条件：
* 绝对根路径：`/`, `/*`。
* 用户家目录：`~`, `$HOME`。
* 未设置默认值的空变量拼接路径：如 `${TARGET_DIR}/`（若前置无赋值或判空逻辑）。




* **R2 - 权限提升与系统逃逸（High 级）：**
* 修改提权配置：向 `/etc/sudoers`、`/etc/pam.d/` 写入数据。
* 危险权限覆盖：`chmod -R 777 /` 或系统关键根级子目录。
* 隐蔽驻留机制：向 `/etc/cron.*`、`/var/spool/cron` 追加未知定时任务。


* **R3 - 远程外联与未授权执行（High/Medium 级）：**
* 管道动态下载执行：`curl ... | bash`、`wget -O- ... | sh`。
* 反弹 Shell 模式：`/dev/tcp/`、`/dev/udp/` 重定向，`nc -e`、`mkfifo` 管道配合。


* **R4 - 动态代码评估（Pending 级，触发 AI）：**
* 调用 `eval`, `source`, `.`, `exec` 且参数包含变量计算或多层命令替换。



### 模块三：静态污点与防御编程推导

* **未校验变量追踪：** 标记脚本入口参数（`$1`, `$@`, `$*`, `read` 输入），检测该变量是否在未经长度检查或判空（如 `[ -z "$VAR" ]`）的情况下，直接作为高危命令的操作目标。
* **防御缺失识别：** 检查危险操作前是否存在前置保护语句（例如 `rm -rf "$DIR/*"` 前是否存在 `[[ -n "$DIR" && -d "$DIR" ]]`）。若缺失，标记为逻辑漏洞。

### 模块四：LLM 语义仲裁引擎（AI Token 驱动层）

仅当第一阶段输出包含 **Pending 标识**、**动态命令** 或 **存在上下文争议的中危操作** 时触发，Prompt 须包含结构化上下文：

* **混淆与编码还原：**
* 对 Base64、Hex 编码、变量切片拼接（如 `${a}${b}` 组合命令）进行静态展开与语义反混淆，还原其底层实际调用的命令。


* **意图合理性研判：**
* 结合脚本的上下文注释、函数命名和前置环境检查，评估操作意图是“合规的业务维护运维（如滚动备份、过期日志定期轮转）”还是“高危破坏行为”。


* **防御性编程重构建议（Auto-Remediation）：**
* 针对检测出的漏洞，生成遵循 Bash 安全编码规范的补丁代码（例如安全引用引号、添加 `set -euo pipefail`、增加路径边界白名单防护）。

## 5. 非功能性需求与性能指标

* **性能时延：**
* 纯静态 AST 规则分析引擎：执行延迟必须控制在 **50ms 以内**（脚本行数 <= 1000 行）。
* 混合 AI 仲裁模式：端到端决策时延控制在 **3 秒以内**。


* **高可用与降级策略：**
* 当网络受限、AI 服务超时或 Token 额度耗尽时，系统能无缝降级为**纯代码离线安全模式**：对于所有 Pending 状态的模糊风险默认收紧为“人工复核 (REVIEW)”，确保生产基线安全。


* **可扩展性：**
* 规则库需解耦，支持以 YAML 或规则策略文件形式动态追加高危命令、敏感路径白名单与黑名单。
