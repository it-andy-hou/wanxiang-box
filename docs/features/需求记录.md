## 2025年11月25日 - 定时任务功能

### 需求背景
当前"脚本执行"和"命令执行"功能创建任务后点击"开始执行"会立即执行，缺乏定时执行能力。需要新增定时执行功能和任务管理页面。

### 功能需求

#### 1. 定时执行选项（采用方案1：默认立即 + 可选定时）

**界面设计原则**：
- ✅ 零额外操作成本：默认立即执行，无需任何勾选
- ✅ 简单可选：需要定时时勾选一个复选框即可
- ✅ 界面简洁：不占用额外空间，体验流畅

**在创建任务时（脚本执行 & 命令执行页面）界面布局**：
```
步骤 1: 选择执行脚本 *
[下拉框]

步骤 2: 选择目标主机 *
[从主机管理选择] [清空选择]

□ 定时执行  💡                     ← 默认不勾选
  └→ 执行时间: [日期选择器]         ← 勾选后才显示

[开始执行] [取消]
```

**交互逻辑**：
- **默认行为**（不勾选"定时执行"）：点击"开始执行" → 立即执行任务（当前行为保持不变）
- **定时模式**（勾选"定时执行"）：
  - 显示日期时间选择器（HTML5 datetime-local）
  - 设置执行时间（不允许选择过去时间）
  - 点击"开始执行" → 任务保存为 `scheduled` 状态，不立即执行
  - 提示用户"定时任务已创建，将在 YYYY-MM-DD HH:mm:ss 自动执行"
  - 自动跳转到"任务调度"页面

#### 2. 任务管理页面（新页面）

**页面名称**：任务调度 / 定时任务管理

**显示内容**：所有**未开始**的定时任务列表

**任务状态筛选**：
- 待执行（scheduled）
- 全部定时任务

**表格列**：
| 任务ID | 任务名称 | 任务类型 | 目标主机数 | 计划执行时间 | 剩余时间 | 创建时间 | 操作 |

**支持的操作**：
- ✏️ **编辑任务**：修改任务配置（主机列表、脚本/命令内容、并发数、超时时间等）
- 🕒 **调整时间**：修改计划执行时间
- ▶️ **立即执行**：手动触发，跳过定时，直接执行任务
- 🗑️ **删除任务**：取消定时任务并删除

#### 3. 自动执行机制

**定时检查器**（主进程）：
- 每分钟检查一次数据库中状态为 `scheduled` 的任务
- 判断 `scheduled_time <= 当前时间`
- 满足条件则自动触发执行
- 执行完成后，任务状态更新为 `completed` / `failed`

**执行流程**：
```
 scheduled（待执行）
     ↓ (到达设定时间)
  running（执行中）
     ↓
 completed / failed（完成/失败）
```

### 技术实现要点

#### 数据库扩展（`task_executions` 表）
新增字段：
```sql
execution_type TEXT DEFAULT 'immediate',  -- 执行类型：immediate(立即)/scheduled(定时)
scheduled_time TEXT,                      -- 计划执行时间（ISO 8601格式）
```

任务状态（`status` 字段）扩展：
- `scheduled`：已调度（等待执行时间到达）
- `pending`：待执行（立即执行任务的初始状态）
- `running`：执行中
- `completed`：已完成
- `failed`：失败
- `cancelled`：已取消

#### 主进程服务
**新增文件**：`src/main/taskScheduler.js`
- 启动定时检查器（每分钟触发）
- 查询 `status = 'scheduled' AND scheduled_time <= NOW()` 的任务
- 调用 `taskExecutor.executeTask()` 执行任务
- 更新任务状态

#### 前端页面
**新增页面**：任务调度管理
- 位置：在"执行历史"前增加导航项
- 文件：`src/renderer/js/scheduledTasks.js`（新建）
- 界面：复用现有表格和弹窗组件

**修改现有页面**：
- `taskExecution.js`：增加执行类型选择和时间选择器
- `commandExecution.js`：增加执行类型选择和时间选择器
- `taskHistory.js`：区分显示立即任务和定时任务

#### 交互流程示例

**创建定时任务**：
1. 用户在"脚本执行"页面配置任务
2. 选择"定时执行"，设置时间为"2025-11-26 14:00:00"
3. 点击"开始执行"→ 任务保存为 `scheduled` 状态
4. 提示"任务已创建，将在 2025-11-26 14:00:00 自动执行"
5. 跳转到"任务调度"页面，显示该任务

**任务管理操作**：
1. 在"任务调度"页面查看待执行任务
2. 点击"调整时间"→ 弹窗修改执行时间
3. 点击"立即执行"→ 确认后立即执行，状态变为 `running`
4. 点击"删除"→ 确认后删除任务记录

**自动执行**：
1. 主进程定时器每分钟检查一次
2. 发现任务A的 `scheduled_time` 已到达
3. 自动调用执行器执行任务
4. 渲染进程如果在"任务调度"页面，实时刷新列表
5. 执行完成后，任务从"任务调度"列表消失，进入"执行历史"

  - 是过滤命令（包含 grep/egrep/fgrep/awk/sed）
  - 有执行跟踪输出（bash -x 产生的 stderr）
  - 无标准输出
  - 退出码为 1
- 前端显示优化：
  - 成功日志显示为“✓ 执行成功，无匹配结果”

**已实现方案（验证时间：2026-02-04）**
当前实现已采用"状态轮询"模式，具体实现：

1. **定时轮询**：使用 `setInterval` 每60秒查询一次数据库，而非依赖单次 `setTimeout` 计算延迟

4. **防重复执行**：使用 `executedTasks` Set 记录已执行任务，防止同一轮询周期内重复触发

**优点**：
- 抵抗系统时间修改：每次轮询都重新获取当前时间，不依赖历史计算
- 抵抗系统休眠：唤醒后自动恢复轮询，不会丢失任务
- 防雪崩：过期任务自动标记为错过，不会瞬间并发执行

### 需求背景

### 决策汇总
| 项 | 决策 |
|---|---|
| 入口位置 | 右上角齿轮 → 全局设置弹窗 → 新增「💾 数据备份」分组 |
| 加密 | ❌ 不加密（明文 JSON，仅本机使用） |
| 导入策略 | 仅「完全覆盖」，不提供合并/选择性导入 |
| 定时频率 | 每天 1 次，备份时间用户自定义 |
| 存储位置 | 仅本地（`<userData>/backups/`） |
| 导入后处理 | **强制重启应用**，避免内存与磁盘不一致 |
| 导入前保护 | **强制自动备份当前数据**到 `backups/before_import/` |
| 5 分钟滚动备份 | 保留作为底层崩溃恢复兜底，UI 不展示（用户无感知） |

### 功能细节

#### 1. 手动导出
- 文件保存对话框，默认文件名：`wxbox-backup-{机器名}-YYYYMMDD-HHmmss.json`
- 文件结构：
  ```json
  {
    "version": "1.0",
    "appVersion": "x.x.x",
    "exportedAt": "2026-05-22T10:30:00Z",
    "hostname": "ANDY-PC",
    "data": { ...完整 database.json 全部表数据 }
  }
  ```
- 大数据量（如 90MB）需显示进度，避免界面卡顿假死

#### 2. 手动导入（高危操作）
- 文件选择对话框 → 校验 `version` 兼容性（不兼容直接拒绝）
- **三重确认**：
  1. 弹窗显示数据量对比：`当前 XX 台主机/YY 脚本/ZZ 历史 → 即将变为 AA/BB/CC`
  2. 输入框二次确认（输入「确认导入」四个字）
  3. 醒目红色警告「此操作不可撤销」
- **导入前强制自动备份**当前数据到 `<userData>/backups/before_import/wxbox-before-import-YYYYMMDD-HHmmss.json`
- 导入流程：
  1. 暂停定时任务调度器、连接监控
  2. 写入新数据到 `database.json`（复用现有原子写入 + rename）
  3. **强制重启应用**（`app.relaunch() + app.exit()`）

#### 3. 定时备份
- 主进程 `setInterval(60s)`，每分钟检查：「上次备份日期 != 今天 且 当前时间 ≥ 设定时间」 → 触发备份
- `app.on('before-quit')` 补一次：当天未备份则退出前补
- 备份文件：`<userData>/backups/daily/wxbox-daily-YYYYMMDD.json`
- 保留策略：默认 30 份，超出删最旧
- 失败处理：磁盘满/路径不可写 → UI 红点角标提醒，不静默失败
- settings 新增字段：
  ```js
  backup_enabled: true,
  backup_time: "02:00",
  backup_keep_count: 30,
  backup_last_at: null   // 上次成功备份时间
  ```

#### 4. 备份历史列表
展示两类（5 分钟滚动备份不展示）：
- 🟢 daily — 每日定时备份（`backups/daily/`）
- 🟡 import — 导入前自动备份（`backups/before_import/`）

操作：
- **恢复**：复用「导入」流程（二次确认 → 备份当前 → 覆盖 → 重启）
- **删除**：单条删除
- **打开目录**：`shell.showItemInFolder` 打开文件管理器

### 涉及的文件清单

**新增**：
- `src/main/backupService.js` — 主进程备份服务（导出/导入/定时调度/历史查询）
- `src/renderer/js/services/backupService.js` — 前端 IPC 封装

### 风险与边界
- **导出文件含明文密码/私钥** — 需在导出弹窗顶部红色提示用户妥善保管
- **大文件**（>200MB）导出/导入需流式处理 + 进度条 + 取消能力

- **重复导入同一文件** → 检测 `exportedAt` 提示用户
- **重启确认** → 重启前提示「应用将在 3 秒后重启完成导入」
