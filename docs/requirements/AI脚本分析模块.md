# AI 脚本分析模块需求文档

> 版本：v1.2（2026-10-14 更新：风险评级校准，避免常规运维脚本被误判为高危）
> 关联文档：`docs/features/ai.md`（分析维度、输出 Schema、Prompt 模板的设计来源）
> 模块定位：在现有脚本管理模块基础上，引入大模型对 Shell 脚本进行安全与健壮性分析，并补充脚本列表批量操作能力。

---

## 1. 背景与目标

运维/开发人员在执行既有脚本前，最关心的是**破坏力、稳定性与生产不可控因素**，而非代码风格。本模块通过接入 OpenAI 兼容的大模型接口，在 5 秒内给出结构化的风险评估卡片，帮助用户快速判断脚本是否可以上线执行。

核心目标：

1. 脚本查看页面可展示 AI 分析结果，并支持重新分析；
2. 脚本编辑页面也可触发 AI 分析（针对当前编辑中的内容）；
3. 分析结果本地存储，内容未变化时不重复调用，避免浪费 token；
4. 脚本列表支持勾选，支持**批量 AI 分析**与**批量删除**（每个脚本独立分析）；
5. 大模型接入配置位于软件设置中，API Key 加密存储于本地。

## 2. 大模型接入设置（软件设置 → 大模型接入）

### 2.1 配置项

| 配置项 | 类型 | 说明 |
| --- | --- | --- |
| 提供商 | 展示 | 当前固定为 `OpenAI 兼容（含自建网关）`，后续可扩展 |
| Base URL | 文本 | 智谱示例：`https://open.bigmodel.cn/api/paas/v4`。基础地址自动补全路径；以 `/chat/completions` 结尾的完整端点原样使用。必须使用 `https://` 地址（明文 `http://` 仅允许 `localhost`/`127.0.0.1` 本机地址，如本地 Ollama） |
| API Key | 密码框 | 用 Electron `safeStorage`（OS 钥匙串派生密钥）AES 加密后存储于本地数据库；已存储时显示 `****`，留空则不修改 |
| 模型 | 文本 | 模型 ID，如 `kimi-k3`、`glm-4` 等 |
| Temperature | 数字 | 0 ~ 2，默认 0.3 |
| ~~流式渲染 (SSE)~~ | 已移除 | 分析调用为非流式（结果需整体解析 JSON），该配置无实际用途，v1.1 移除 |
| 测试连接 | 按钮 | 发送一条最小消息验证地址/Key/模型可用性，显示成功或具体错误 |
| 累计消耗 | 展示 | 从接口 usage 统计：累计分析次数、总 token（输入/输出分计），展示于本分组底部；底部状态栏同步展示累计 token（脚本数统计旁，悬停显示明细） |

### 2.2 安全要求

- API Key 仅在主进程内存中解密使用，任何 IPC 通道不回传 Key 原文（仅回传 `hasKey` 布尔值）；
- `safeStorage` 不可用（部分 Linux 环境）时降级为明文存储并明确提示用户，不阻塞功能；
- Base URL 协议校验：非 `https://` 且非 localhost 的地址拒绝保存。

## 3. AI 分析功能

### 3.1 分析维度与输出格式

沿用 `docs/features/ai.md` 定义，并增加评级校准（v1.2，防止过度报警）：

- System Prompt：资深 Linux 自动化与基础设施安全工程师角色，聚焦变量展开风险、错误中断策略、幂等性、资源清理、外部依赖；
- **五档分级标准**（基于可逆性×影响范围）：
  - CRITICAL：仅在出错/变量为空时即造成不可逆大范围破坏（空变量 rm -rf 路径坍缩、mkfs/dd 直写磁盘、curl|bash）
  - HIGH：明确的不可逆数据破坏且防护不足（rm -rf 固定业务路径无确认无备份、覆盖写入无备份）
  - MEDIUM：影响大但可恢复（服务重启/停止、防火墙变更、chmod -R 777、kill 进程）
  - LOW：小范围、易恢复或低概率影响（清理明确的临时目录、临时文件操作）
  - SAFE：只读查询/纯计算无副作用（df/free/ps/cat 等）
- **评级校准原则**：评级反映「事故概率×影响」而非问题数量；纯规范性缺陷（缺 set -e/trap/幂等/参数校验）单独不使评级超过 MEDIUM；常规运维操作按可恢复性评级；只读巡检一律 SAFE。
- User Prompt：要求严格按 JSON Schema 返回：`summary`（purpose / risk_level / is_idempotent / requires_root）、`critical_risks[]`（line / snippet / issue / solution）、`dependencies`（commands / env_vars）、`robustness_score`、`optimized_snippet`；
- risk_level 五档：`CRITICAL | HIGH | MEDIUM | LOW | SAFE`。

### 3.2 结果展示（交通灯法则）

查看脚本弹窗新增「AI 分析」卡片（位于脚本内容下方）：

```
+------------------------------------------------------------+
| [高危 HIGH]  权限: Root  幂等: 否                            |
| 功能摘要: 清理 /data 目录下的归档日志并压缩发送到备份机        |
+------------------------------------------------------------+
| [!] 严重风险 (N 项)                                          |
|  - 行 14: 变量 $BACKUP_DIR 未赋默认值，可能造成根目录误删     |
|    建议: ...                                                 |
+------------------------------------------------------------+
| [-] 依赖: jq, rsync, ssh 免密 | 健壮性评分: 4/10              |
+------------------------------------------------------------+
| [>] 推荐改动（关键修复代码）                                  |
+------------------------------------------------------------+
| 分析时间: 2026-10-14 12:00 · 模型: kimi-k3                  |
| 消耗: 12,345 tokens (输入 10,000 / 输出 2,345)              |
+------------------------------------------------------------+
```

- 卡片底部展示**分析时间、所用模型与本次 token 消耗**（来自接口 usage，网关不返回时省略）；
- 解析失败（模型未返回合法 JSON）时降级展示原始文本并标记「解析失败」；
- AI 结果**独立展示**，不覆盖规则引擎（RiskAnalyzer）的「风险等级」标签，两套评估互不干扰。

### 3.2.1 列表页 AI 角标

脚本列表名称列在规则引擎角标（高危/中危/普通）之后展示 AI 角标，五档 + 两个异常态：

| 角标 | 含义 |
| --- | --- |
| AI:严重 / AI:高危 / AI:中危 / AI:低危 / AI:安全 | 对应 CRITICAL/HIGH/MEDIUM/LOW/SAFE，有有效分析结果时展示（悬停显示分析时间） |
| AI:过期（灰） | 脚本内容已修改，结果可能过期，建议重新分析 |
| AI:异常 / AI:解析失败（红） | 分析调用失败或返回无法解析 |

- 无分析记录的脚本不显示 AI 角标；
- 单脚本/批量分析完成后角标实时刷新。

### 3.3 分析入口

| 入口 | 行为 |
| --- | --- |
| 查看脚本弹窗 | 打开时自动读取本地缓存结果（不自动调用模型）；提供「AI 分析 / 重新分析」按钮手动触发 |
| 编辑脚本弹窗 | 提供「AI 分析」按钮，对**当前编辑器中的内容**分析（按内容哈希命中缓存则直接复用）；新脚本未保存前也可分析（不落库） |
| 脚本列表批量 | 勾选多个脚本 → 批量 AI 分析（见 3.5） |

### 3.4 结果缓存（避免重复消耗 token）

- 新建数据表 `script_ai_analyses`（simple-db JSON 存储），每个脚本仅保留最新一条记录；
- 记录字段：`id、script_id、script_name、content_hash（sha256）、model、result（解析后 JSON）、raw（原始返回）、status（success / parse_error / error）、error、created_at`；
- 缓存命中条件：`script_id` 相同 **且** `content_hash` 相同——脚本内容一旦修改，旧结果自动失效；
- 「重新分析」/「强制重新分析」忽略缓存重新调用；
- 删除脚本时级联删除其分析记录。

### 3.5 批量 AI 分析

- 脚本列表新增勾选列（表头全选 + 行勾选，与主机管理页交互一致）；
- 勾选后显示批量操作栏：`已选择 N 个脚本` + `批量 AI 分析` + `批量删除`；
- 批量分析弹窗：
  - 默认勾选「跳过已分析且内容未变化的脚本」（按缓存判断），可切换为强制重新分析；
  - 开始前提示将消耗的脚本数量（估算 token 风险），超过阈值（如 20 个）二次确认；
  - 并发上限 2（可配置常量），逐个独立分析、独立落库，单个失败不影响其他；
  - 实时进度条 + 每行脚本状态（等待/分析中/成功/失败/跳过）；
  - 支持取消：停止派发新任务，已完成的结果保留；
  - 完成后汇总：成功 N / 失败 N / 跳过 N，并刷新列表缓存角标。

### 3.6 批量删除

- 勾选脚本 → 批量删除 → 确认弹窗（列出数量，若脚本被任务引用则提示数量）；
- 删除时级联清理：快捷面板条目、AI 分析记录；执行历史保留（不做级联，历史记录中的脚本名已冗余存储）；
- 删除范围以当前筛选视图可见的勾选项为准。

### 3.7 未配置 / 异常状态

- 未配置大模型时，AI 分析按钮置灰并提示「请先在 设置 → 大模型接入 中完成配置」；
- 网络失败 / Key 无效 / 模型不存在等错误，在按钮旁或卡片位置展示具体错误信息；
- 脚本内容超过 30000 字符时拒绝分析并提示（防止超上下文）。

## 4. 技术实现要点

| 项 | 方案 |
| --- | --- |
| 主进程服务 | 新增 `src/main/aiService.js`：配置读写、safeStorage 加解密、`/chat/completions` 调用（Node 18 原生 fetch）、Prompt 组装、JSON 容错解析、缓存读写、批量队列 |
| JSON 容错 | 剥离 ```json 围栏 → `JSON.parse` → 失败则截取首个 `{` 到末个 `}` 重试 → 仍失败标记 `parse_error` 保留原文 |
| IPC 通道 | `ai:getSettings / ai:saveSettings / ai:testConnection / ai:analyze / ai:getAnalysis / ai:getAllAnalyses / ai:batchAnalyze / ai:batchCancel / ai:deleteAnalyses`；批量进度通过 `webContents.send('ai:batch-progress')` 推送 |
| token 统计 | chat 返回 content + usage；单次消耗存入分析记录 usage 字段并展示在卡片底部；累计值（次数/总 token/输入/输出）存 settings.ai，展示于设置页与底部状态栏（实际调用才计数，命中缓存不计，分析完成后实时刷新） |
| 流式 | 不启用 SSE；相关配置项已移除 |
| 数据存储 | simple-db 新增 `script_ai_analyses` 表（`DEFAULT_DATA` 注册，旧库自动合并） |
| 渲染层 | 新增 `src/renderer/js/services/aiService.js`（IPC 封装）与 `src/renderer/js/aiAnalysisUI.js`（卡片渲染 + 批量弹窗） |
| 设置 UI | 扩展 `app.js` 全局设置弹窗，新增「大模型接入」分组 |
| 流式 | 本期分析不启用 SSE；设置项已移除 |

## 5. 验收标准

1. 设置页可配置 Base URL / API Key / 模型 / Temperature，测试连接返回明确成功/失败原因；Key 重启后仍可用且不回传明文；
2. 查看脚本弹窗：有缓存直接展示；无缓存点「AI 分析」调用模型并展示交通灯卡片；「重新分析」强制刷新；
3. 编辑脚本弹窗：可对当前内容分析；内容修改后旧缓存不命中；
4. 同一脚本内容不变时第二次分析不发起网络请求（token 零消耗）；
5. 脚本列表可勾选、全选；批量删除后列表、目录计数、快捷面板同步清理；
6. 批量分析有进度、可取消、单个失败不影响整体，完成后每行结果独立可查看；
7. 未配置模型时各入口给出明确引导，不报未知错误。
