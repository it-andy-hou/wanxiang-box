# 执行监控无法滚动修复

## 问题描述
脚本执行时，执行监控区域无法上下滚动查看（进度条、统计格被挤出视口后滚不回来）。

## 根因
切页逻辑对 `.page` 元素设置 inline `style.display = 'block'`（app.js `switchPage` 与 navigation.js `switchPageDisplay` 两处重复实现），inline 样式覆盖了 CSS 的 `.page { display: flex }`，导致整条 flex 高度约束链断裂：

```
.page (display: flex → 被 inline block 覆盖)
└── .page-content (flex:1 + min-height:0 失效)
    └── #taskConfigSection (高度 = 内容自然高度 1444px，超过视口 773px)
```

- `.page-content--scroll` 的 `overflow-y: auto` 因自身高度=内容高度而永不触发；
- 溢出内容被 `.page` 的 `overflow: hidden` 直接裁剪；
- 结果容器（`.result-overview-container` 600px 固定高）内层滚动不受影响。

**暴露时机**：脚本选择改为搜索式面板后配置区变高（约 +200px），监控头部被挤出视口，该陈年布局缺陷才显形；此前配置区较矮（原生 select），监控头部仍在视口内。

## 修复方案
两处切页代码将 `targetPage.style.display = 'block'` 改为 `targetPage.style.display = ''`（移除 inline 声明），让 CSS 的 `display: flex` 接管。HTML 中 `.page` 初始 `style="display: none"` 由隐藏逻辑正常设置，无 CSS `display: none` 规则，置空后页面正常显示。

- 修改文件：`src/renderer/js/app.js`（switchPage）、`src/renderer/js/navigation.js`（switchPageDisplay）

## 验证（CDP 远程诊断）
修复前：`.page` computed display = block；page-content clientHeight 1444 = scrollHeight，pcMaxScroll = 0（不可滚动）。
修复后：`.page` display = flex；page-content clientHeight 708、scrollHeight 1444，pcMaxScroll = 736，程序化滚动 `scrollTop += 200` 成功；结果容器内层滚动不受影响。

该修复同时恢复了**所有页面**的 flex 高度链（此前全部页面都以 block 布局运行，列表 flex 自适应效果被打折）。

## 命令执行页专项验证（2026-09-12 补充）
命令执行页与脚本执行页结构同构（`.page > .page-content--scroll > 配置区 + 监控区 + 结果容器`），且无独立切页逻辑，切页统一走 app.js/navigation.js，因此被本次修复自动覆盖。CDP 实测（模拟执行中：配置区展开 + 监控区显示 + 注入 20 条结果）：
- `#page-commands` computed display = flex；
- page-content clientHeight 708（受限于视口）、scrollHeight 1287，pcMaxScroll = 579，程序化滚动成功；
- 结果容器（600px 固定高）内层滚动正常（rcMaxScroll = 430）。

无需额外改动。
